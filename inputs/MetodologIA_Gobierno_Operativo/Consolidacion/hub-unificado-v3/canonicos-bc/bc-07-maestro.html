2. Definición sin Confusiones ▼

¿QUÉ ES BC-07?

BC-07 es un bootcamp empresarial intensivo que enseña a equipos a diseñar, construir, desplegar y gobernar sistemas de agentes autónomos basados en IA para resolver problemas de negocio reales.

Esto significa:

Aprender arquitecturas de agentes (patrones probados, anti-patrones, topologías)
Construir agentes funcionales en Claude, GPT-4, n8n y Make
Implementar orquestación multi-agente para flujos complejos
Diseñar gobernanza y seguridad para sistemas autónomos
Capstone: desplegar 3+ agentes que resuelven problemas reales de la organización

¿QUÉ NO ES BC-07?

No es...Porque...
Curso de promptingNo enseña técnicas de prompt design (eso es WS-02)
Consultoría de implementaciónNo construimos agentes *para* usted; construimos *con* usted
Certificación de ChatGPTNo es sobre usar herramientas; es sobre diseñar sistemas
Capacitación genérica en IAEs específicamente agent architecture + deployment
Puente a Digital ChampionsEs el *prerequisito recomendado* que prepara para DC (PE-02)

5. Problema que Resuelve ▼

El Vacío

Hoy, muchas organizaciones están en este estado:

✅ Personas saben usar ChatGPT / Claude
✅ Han hecho experimentos con prompting
✅ Entienden el potencial de IA
❌ Pero no saben cómo construir sistemas autónomos que funcionen sin supervisión humana constante
❌ No tienen arquitecturas para coordinar múltiples agentes
❌ Carecen de gobernanza y seguridad para sistemas agentos en producción
❌ No pueden escalar de "un agente en Slack" a "10 agentes en operaciones"

El Salto

BC-07 enseña ese salto:

DE:                                  A:
└─ Usar ChatGPT/Claude              ├─ Arquitectura de agentes
└─ Un prompt a la vez               ├─ Orquestación multi-agente
└─ Respuestas puntuales             ├─ Ciclos de feedback automatizados
└─ Supervisión manual constante     ├─ Gobernanza y seguridad
                                    └─ Sistemas que mejoran con tiempo
6. Arquitectura Curricular — 6 Módulos, 24 Horas ▼

M0: Landscape Agéntico + Assessment Individual (2h)

Objetivo: Establecer baseline de comprensión y contexto.

Contenidos:

Estado del arte en agent architecture (2025-2026)
Tipología de agentes: reactivos, deliberativos, sociales
Casos de uso empresariales reales (finanzas, operaciones, soporte)
Assessment: qué sabe cada participante hoy
Proyección: qué construirá durante capstone

Entregable: Plan individual + tema de capstone asignado

M1: Arquitectura de Agentes — Patrones y Anti-Patrones (4h)

Objetivo: Entender *cómo* funcionan los agentes y qué puede salir mal.

Contenidos:

Anatomía de un agente: percepción → razonamiento → acción
Patrones arquitectónicos probados:
Tool-calling (Claude + GPT-4 native)
Orchestration (n8n, Make, LangChain)
Agentic loops (reasoning → action → observation → repeat)
Anti-patrones que matan proyectos:
"Razonamiento infinito" (agente que nunca termina)
"Decisiones sin contexto" (memory gaps)
"Hallucination al actuar" (agent inventa acciones inexistentes)
"Falta de monitoreo" (agent en producción sin observability)
Gobernanza en la arquitectura: cómo embeber seguridad desde el diseño
Topologías multi-agente: supervisor, especializado, competitivo

Ejercicio: Diseñar (en papel) arquitectura para un caso de uso asignado. Identificar anti-patrones.

Entregable: Architecture Decision Document (ADD) de 2 páginas por persona

M2: Construcción de Agentes — Claude, GPT-4, n8n, Make (4h)

Objetivo: Construir agentes reales.

Contenidos:

Claude Agents:
Tool use nativos
Claude Code (ejecución en-browser)
Vision + agent reasoning
Patterns de iteración
OpenAI Agents (GPT-4 + Function Calling):
Parallel tool calling
Async workflows
Cost optimization
Low-code orchestration (n8n / Make):
Triggers, conditions, actions
Conectores (50+ integraciones)
Error handling y retries
Logging y debugging
Hybrid approaches:
LLM intelligence + RPA execution
Custom code (Python) para lógica compleja

Hands-on: Cada participante construye 1 agente funcional (elegir stack según caso de uso).

Entregable: Agent v1.0 deployada en sandbox + code repository + test cases

M3: Orquestación Multi-Agente (4h)

Objetivo: Coordinar múltiples agentes en flujos reales.

Contenidos:

Patrones de coordinación:
Supervisor (1 agente master, múltiples workers)
Colaborativo (agentes negocian)
Competitivo (best-of-N)
Jerárquico (agentes anidados)
Comunicación inter-agente:
Message passing (APIs, queues, webhooks)
Shared context (databases, vector stores)
Consensus mechanisms
Manejo de estado distribuido:
Consistency patterns
Idempotency
Timeout y recovery
Performance en flujos largos:
Token management
Costo y latencia
Optimización de llamadas LLM

Caso de estudio: Workflow de 3+ agentes: análisis → decisión → acción.

Entregable: Multi-Agent Orchestration Blueprint (diagrama + pseudocódigo)

M4: Gobernanza, Ética y Seguridad para Agentes (3h)

Objetivo: Asegurar que agentes sean seguros, auditable y cumplidores.

Contenidos:

Gobernanza operacional:
Quién puede crear agentes
Quién aprueba despliegues
Auditoría de acciones agentas
Rollback y remediation
Riesgos agentos:
Hallucinations en contextos críticos
Drift (comportamiento que cambia)
Escalation sin límite (agente actúa más allá de autoridad)
Data leaks (agente expone información sensible)
Frameworks de control:
Human-in-the-loop (cuándo validar manualmente)
Rate limiting y cost caps
Acción permitidas (whitelist vs. blacklist)
Encryption y credential management
Ética y compliance:
Transparencia (users saben que es un agente)
Bias en decisions agentas
LGPD / GDPR para agentes en EU
Responsabilidad: quién es accountable si agente causa daño

Debate: Escenarios éticos (agente recomienda despido, agente negocia con clientes sin supervisión)

Entregable: Enterprise AI Governance Framework v1 (draft, 5-7 páginas) aplicable a la organización

M5: Lab de Integración + Capstone (4h + 3h presentación)

Objetivo: Llevar agentes a producción y demostrar competencia.

Contenidos:

Integración real:
Conectar agentes a sistemas legacy (SAP, Oracle, Salesforce)
APIs, webhooks, scheduled execution
Logging, monitoring, alerting
Disaster recovery
Testing en producción:
Canary deployments
A/B testing contra baseline
Rollback automático
Capstone requirements:
Mínimo 2 agentes completamente funcionales
Cada uno resolviendo problema real de negocio
End-to-end: desde arquitectura a medición
ROI calculator completado
Team adoption playbook escrito

Presentación final (3h):

20 min por equipo (2-3 personas c/u)
Demo live de agentes
ROI y métricas
Q&A con jurado técnico
Certificación condicional a aprobación

Entregable:

3+ Custom Agents deployed
Agent Architecture Blueprints (documentadas)
Automation Workflow live (n8n/Make)
ROI Calculator per agent
Team Adoption Playbook
Enterprise AI Governance Framework (final)

8. Modelo de Evaluación y Certificación ▼

Participación (Condición Necesaria)

Asistencia: Mínimo 90% de horas (21.6/24h)
Entregas en tiempo: ADD, Agent v1.0, Blueprint, Framework contribution
Participación en debates y ejercicios en clase

Sin estos: Certificado de "Asistencia" nada más.

Competencia (Condición Suficiente)

Evaluada a través del Capstone: 2 Agentes Operacionales

Criterios:

Agente 1: Resuelve caso de uso real (no dummy data)
Agente 2: Demuestra patrón diferente al primero
Architecture: Decisiones justificadas, sin anti-patrones críticos
Testing: Casos de prueba documentados, >80% success rate
Operación: Runbook, monitoreo, plan de contingencia
ROI: Cálculo realista de savings o value
Presentation: Demo clara, responde preguntas técnicas

Evaluadores:

Facilitador técnico (principal)
CTO / Head of Innovation de la organización (co-evaluador)

Certificados Emitidos

Validez del certificado: 2 años desde emisión. Refresco con 4h de actualización.

15. Protocolo de Contingencia ▼

Escenarios y Respuestas

Escenario A: Facilitador se enferma

Respuesta:

1Notificar cliente dentro de 24h
2Reschedule a facilitador backup (dentro de 1 semana)
3Si no disponible: descuento 10% en bootcamp, opción refund
4Continuidad: asistente técnico puede continuar labs mientras se busca remplazo

Escenario B: Cliente queda sin casos de uso antes de capstone

Respuesta:

1Facilitador ayuda a idear casos reales en 2h session
2Si aún imposible: capstone puede ser "agente genérico" (demo, no producción)
3Posterior opción de "Operationalization Sprint" (8h) con casos reales

Escenario C: Problemas de infraestructura (APIs down, VPN, etc.)

Respuesta:

1Bootcamp continúa con sandbox local / simulado (código disponible)
2SI problema persiste >4h: cliente recibe descuento prorrateado (COP 50k per hora)
3NO es justificación para cancelación completa (a menos que >50% del bootcamp afectado)

Escenario D: Capstone rechazado (no cumple estándar)

Respuesta:

1Feedback detallado de por qué (anti-patrones, coverage insuficiente)
2Opción de remediación: 4h de office hours adicionales, re-evaluación en 2 semanas
3Si aún falla: certificado de "participación", opción de "Operationalization Sprint" pago

Escenario E: Cliente quisiera cambiar de track a mitad

Respuesta:

1De "Personal" a "Empresa": pay diff (COP 16.8M) si estamos antes de M3
2De "Empresa" a "Personal": no permitido (degradación de servicio)
3A track diferente (ej. BC-04): crédito de 50% bootcamp pagado hacia nuevo
