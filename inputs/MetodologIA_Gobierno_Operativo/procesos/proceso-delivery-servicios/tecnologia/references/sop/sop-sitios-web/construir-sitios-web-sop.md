## Propósito del Servicio

Diseñar, construir y publicar presencia digital profesional que amplifica la marca personal o comercial del cliente. El sitio web es la **BASE de la presencia digital** — todo lo demás (redes, contenido, automatizaciones) se conecta aquí.

**Filosofía Core**: *"Tu sitio web es tu sede digital. No es un gasto — es una inversión que trabaja 24/7."*

## 4 Tipologías de Sitios Web

### Landing Page (1 página)
- **Caso de uso**: Validar oferta, lanzamiento de producto, evento puntual, lead capture
- **Alcance**: 1 página con form de contacto
- **Tiempo**: 1 semana | **Inversión**: COP ~$500K

### Sitio Institucional (5-10 páginas)
- **Caso de uso**: Marca personal, PYME, freelancer, startup early-stage
- **Alcance**: Home + About + Servicios + Blog + Contacto + Legal
- **Tiempo**: 3 semanas | **Inversión**: COP ~$3M

### E-Commerce (Catálogo + Pagos)
- **Caso de uso**: Venta de productos o servicios digitales
- **Alcance**: Catálogo dinámico, carrito, pasarela de pago, inventario
- **Tiempo**: 6 semanas | **Inversión**: COP ~$12M

### Portfolio/CV Digital
- **Caso de uso**: Profesional creativo (diseñador, fotógrafo, desarrollador)
- **Alcance**: Galería de proyectos, testimonios, formulario de contacto
- **Tiempo**: 2 semanas | **Inversión**: COP ~$1.5M

## Stack Tecnológico Soportado

### No-Code (Menor mantenimiento)
- **Framer**: Excelente para portfolios, animaciones nativas
- **Webflow**: Control total de diseño + hosting incluido
- **Carrd**: Landing pages ultrarrápidas
- **WordPress + Elementor**: Flexible, SEO nativo

### E-Commerce Especializado
- **Shopify**: Plataforma completa, pagos integrados, apps marketplace
- **WooCommerce**: WordPress plugin, bajo costo, comunidad grande
- **TiendaNube**: Plataforma LATAM, payment integrations locales

### Custom (Control máximo)
- **React / Next.js**: SPAs, JAMstack, serverless functions
- **Astro**: Static site generation, performance extrema
- **HTML/CSS/JS Puro**: Máximo control, mínimas dependencias

### Hybrid (Template + Personalización)
- Comprar template premium (Themeforest) + customizar
- IA genera estructura → Humano refina diseño
- Stack híbrido: Webflow para diseño + Serverless functions para lógica compleja

## Proceso de Entrega (Paso a Paso)

### 1. DISCOVERY (Día 1-2)
**Definir identidad y estrategia digital**

- Marca: valores, story, diferenciador vs competencia
- Público objetivo: persona, edad, qué busca, donde vive online
- Competidores: analizar 3-5 sitios de referencia (estructura, copywriting, CTA)
- Inspiración visual: mood board (colores, tipografía, imágenes)
- Contenido existente: qué tiene el cliente, qué falta
- Objetivos: leads, ventas, authority, reclutamiento

**Entregable**: Brief creativo (2-3 páginas) + moodboard + roadmap de contenido

### 2. DISEÑO VISUAL (Día 3-7)
**Aprobación visual antes de construir**

- Moodboard: paleta de colores, tipografía, estilos
- Wireframe: estructura de 3-5 páginas principales
- Mockup: diseño visual completo (hero, cards, footer)
- Versión mobile: verificar responsive
- Gate: **Cliente aprueba diseño antes de desarrollo**

**Herramientas**: Figma, Adobe XD, Sketch

### 3. CONTENIDO EN PARALELO (Día 5-10)
**Redacción + Assets**

- Copywriting: homepage, servicios, about, FAQs (MetodologIA genera con IA + revisión)
- Imágenes: fotos del cliente (profesional) O stock photos (Unsplash, Pexels)
- Vídeos: hero video (10-15seg), testimonios, product demos
- SEO keywords: investigación de términos por página

**Socios**: Fotógrafo (si needed), copywriter IA, stock asset library

### 4. DESARROLLO SPRINT 1: CORE (Día 8-14)
**Construir home + páginas principales**

- Home: hero + value props + CTA principal
- Página de servicios / productos
- Página About: historia, equipo, valores
- Contacto: formulario con validación + envío a email
- Navegación: header + footer + menu mobile
- Demo con cliente: feedback inicial

**Stack**: Decidir entre no-code vs custom basado en complejidad

### 5. DESARROLLO SPRINT 2: FEATURES (Día 15-21)
**Completar funcionalidad para Institucional+**

- Blog: posts, categorías, búsqueda, RSS
- Formularios avanzados: testimonios, suscripción, newsletter
- Integraciones: Google Analytics, Mailchimp, CRM
- SEO: meta titles, descriptions, open graph, sitemap
- Performance: image optimization, lazy loading, caché

**Criterios**: Todos los formularios funcionales, analytics activo

### 6. DESARROLLO SPRINT 3: E-COMMERCE (Día 22-35, solo si E-Com)
**Catálogo dinámico + pasarela de pagos**

- Catálogo de productos: imágenes, descripciones, precios, SKUs
- Carrito de compras: agregar/quitar, actualizar cantidad
- Pasarela de pago: Stripe, PayU, MercadoPago (según país)
- Inventario: stock management, notificaciones bajas
- Envíos: integración con carrier, calculador de costo
- Confirmación de pedido: email + dashboard para cliente

### 7. TESTING (2-3 días)
**QA: Cross-browser, mobile, funcionalidad, seguridad**

- Cross-browser: Chrome, Firefox, Safari, Edge (desktop + mobile)
- Velocidad: PageSpeed Insights ≥80/100 (mobile)
- Formularios: testing cada input, validaciones, edge cases
- Links: 0 broken links, 0 404s
- Pagos: transacciones test en sandbox
- Accesibilidad: WCAG 2.1 nivel AA (botones grandes, contraste, alt text)

**Criterios de aceptación**: Ver sección "Definition of Done"

### 8. LAUNCH (1 día)
**Go-live checklist**

- Comprar/transferir dominio (si needed)
- Configurar DNS (MX, A records, CNAME)
- SSL: instalar certificado HTTPS (Let's Encrypt gratis)
- DNS propagation wait (24-48h)
- Analytics: GA4 + Search Console configurados
- Backup automático activado
- Monitoreo: Uptime robot, error tracking (Sentry)

**Go-live step-by-step**:
1. QA final en staging environment
2. Backup de todo
3. DNS apunta a nuevo hosting
4. Verificar HTTPS, load test
5. Notificar a cliente: sitio live
6. Monitorear primeras 24h

### 9. TRAINING (1h)
**Capacitar al cliente**

- Cómo acceder al sitio (URL, credenciales admin si CMS)
- Editar contenido: textos, imágenes (WordPress / Webflow admin)
- Agregar productos (si e-commerce)
- Ver analytics: GA4 dashboard
- Reportar bugs: email support
- Escalation: cuando contactar MetodologIA vs Soporte L1

### 10. SOPORTE (30 días)
**Post-launch: ajustes y bug fixes**

- Response time: bloqueante <4h, normal <24h
- Alcance: bugs reales, cambios UI menores (<1h), ajustes SEO
- NO incluye: rediseño, nuevas features, cambios de estrategia
- Hosting: incluido 3 meses. Después: cliente paga o MetodologIA cobra

## 10x Elevation Protocol: 7 Dimensiones

### 1. SUPUESTOS EXPLÍCITOS
**¿Qué damos por sentado?**

- S1: Cliente tiene identidad visual clara (logo, paleta de colores)
  - Si NO → diseñar desde cero (+1 semana, +$500K)
- S2: Cliente puede proporcionar contenido (textos, fotos) con calidad mínima
  - Si NO → MetodologIA genera con IA pero requiere aprobación
- S3: El sitio web es canal de ATRACCIÓN, no único canal de venta
  - Si es e-commerce: requiere Google Ads, email marketing, redes sociales para conversión
- S4: Dominio existente o cliente autoriza compra de dominio
- S5: Volumen esperado: <100K visitas/mes (para sitios institucionales)
  - Si >100K: requiere arquitectura más robusta (caché, CDN)
- S6: Cliente no requiere compliance regulatorio (GDPR, HIPAA, PCI)
  - Si sí → proyecto especial con arquitecta de seguridad
- S7: Timeframe realista: cliente entiende que diseño web es 6-10 semanas, no 2

**Validación**: En Discovery, confirmar S1-S7. Si falla alguno → ajustar scope, tiempo o inversión.

### 2. LÍMITES
**¿Qué NO incluye un sitio web estándar?**

| Límite | Razón |
|--------|-------|
| App web compleja (CRM, ERP) | Requiere arquitecta diferente, no es "sitio web" |
| Más de 2 idiomas | Traducciones = 2x testing, 2x SEO |
| Integraciones complejas (100+ APIs) | Testing exponencial, mantenimiento insostenible |
| Pagos recurrentes/suscripción avanzada | Requiere compliance, webhooks, dunning |
| Datos sensibles sin encriptación | Compliance/GDPR, requiere auditoría seguridad |
| Machine learning / IA generativa | Requiere especialista diferente |
| Geo-targeting / multi-region | Requiere CDN distribuido, arquitecta |
| Support 24/7 | No es alcance estándar, contrato especial |

**Gate**: Si cliente necesita algo de esta lista → proponer proyecto separado o rechazar.

### 3. CRITERIOS BINARIOS
**Sí / No. No hay grises.**

| Criterio | Sí ✅ | No ❌ |
|----------|-------|-------|
| **PageSpeed ≥80 (mobile)?** | Acepta | Rechaza (optimizar) |
| **Responsive: mobile + desktop?** | Acepta | Rechaza (CSS media queries) |
| **SSL/HTTPS activo?** | Acepta | Rechaza (instalar certificado) |
| **0 broken links?** | Acepta | Rechaza (auditoría) |
| **Formularios funcionales?** | Acepta | Rechaza (testing) |
| **SEO básico presente?** (meta tags, sitemap) | Acepta | Rechaza (SEO audit) |
| **Cliente puede editar contenido?** | Acepta | Rechaza (setup CMS) |
| **Backup automático activo?** | Acepta | Rechaza (configurar) |

**Proceso**: No entregar si alguno es No.

### 4. CASOS BORDE (5-7 Escenarios Críticos)

**CB-01: Cliente sin Identidad Visual**
- Cliente no tiene logo, paleta de colores, o fuentes definidas
- **Síntoma**: "Diseña lo que creas que va mejor"
- **Fallback**: MetodologIA diseña identidad + sitio (costo extra ~$1.5M, tiempo +1 semana)
- **Alternativa**: Usar template premium + minimal customization

**CB-02: DNS / Dominio Inaccesible**
- Cliente tiene dominio pero no sabe acceder panel de control de DNS
- **Síntoma**: "No tenemos acceso a GoDaddy" O "hosting expiró"
- **Fallback**:
  1. Sitio se entrega con dominio temporal
  2. Cliente (o MetodologIA pagada) hace transferencia después
  3. Documentar steps de DNS migration
- **Salida**: Go-live en URL temporal, migration task pending

**CB-03: Pasarela de Pago Rechaza al Cliente**
- E-commerce: cliente intenta registrarse en Stripe/PayU pero es rechazado
- **Síntoma**: "No califico para Stripe porque soy del país X"
- **Fallback**:
  - Ofrecer alternativa local (MercadoPago, Wompi, PSE)
  - O defer pagos a integraciones futuras, lanzar con "contáctame para pedir"
- **Salida**: Sitio funcional sin pagos online temporalmente

**CB-04: Contenido del Cliente es Insuficiente**
- Cliente tiene 3 fotos y 2 párrafos para 10 páginas
- **Síntoma**: "Aquí dice todo lo que tenemos"
- **Fallback**:
  1. MetodologIA genera copy con IA + placeholder images
  2. Scheduled review: cliente aprueba/ajusta
  3. Cliente proporciona fotos profesionales
- **Salida**: Sitio live con contenido temporal, mejora iterativa

**CB-05: Rediseño Mid-Project**
- Cliente aprobó diseño viernes, lunes dice "todo mal, empecemos de nuevo"
- **Síntoma**: "He estado pensando... algo no cuadra"
- **Fallback**:
  1. Congelar proyecto
  2. Proponer change request formal: +2 semanas, +50% costo
  3. Opción: cancelar, devolver 50% presupuesto
- **Salida**: Contrato modificado + aprobación ejecutiva

**CB-06: Migración SEO desde Sitio Antiguo**
- Cliente tiene sitio viejo con 100 posts, keywords posicionadas en Google
- **Síntoma**: "No quiero perder mi SEO"
- **Fallback**:
  1. Auditoría SEO: mapear URLs viejas → nuevas
  2. Setup 301 redirects
  3. Resubmit sitemap en Search Console
  4. Monitoring: 2-3 meses hasta estabilización
- **Salida**: Preservar 80-90% del tráfico, mejorar a partir de ahí

**CB-07: Cambio de Cliente / Rotación de Equipo**
- Proyecto empieza con contacto X, a los 2 meses sale del cliente
- **Síntoma**: Nuevo contacto desaprueba decisiones de X, quiere pivotar
- **Fallback**:
  1. Reunión con nuevos stakeholders
  2. Documentar cambios explícitamente en change request
  3. Si scope aumenta >20%: increase budget or timeline
- **Salida**: Alignment formal, contrato actualizado

## Criterios de Aceptación (Definition of Done)

Antes de entregar, validar 100% de estos:

- ☐ PageSpeed Insights: Mobile ≥80/100, Desktop ≥85/100
- ☐ Responsive: testeado en 320px, 768px, 1024px, 1440px viewports
- ☐ Cross-browser: Chrome, Firefox, Safari, Edge (desktop + mobile)
- ☐ SSL/HTTPS: válido, sin warnings en navegador
- ☐ SEO básico: meta titles, descriptions, h1-h6 hierarchy, sitemap.xml, robots.txt
- ☐ 0 broken links: verificado con herramienta (Screaming Frog)
- ☐ 0 imágenes missing: 404s auditadas
- ☐ Formularios: todos funcionales, validaciones activas, emails se envían
- ☐ Analytics: GA4 instalado, eventos principales configurados
- ☐ Backup automático: verificado en hosting
- ☐ Cliente puede editar contenido: tested con credenciales reales
- ☐ Documentación: guía de uso + admin guide en Notion/PDF
- ☐ Performance: tiempo de carga <3seg, Lighthouse green
- ☐ Accesibilidad: WCAG 2.1 AA (botones clickeables, contraste, alt text)
- ☐ Pagos (si e-com): transacciones test exitosas
- ☐ Seguridad básica: sin console errors, CORS configurado, headers de seguridad

**Go/No-Go**: Viernes. Si <12/15 es ✅ → no va a producción.

## 5+ Anti-Patterns (Trampas Comunes)

**AP-01: El Sitio Bonito Vacío**
- Diseño premium, animaciones hermosas, pero contenido sin valor
- Resultado: usuarios rebotan en 3 segundos, 0 conversión
- **Regla**: Contenido primero (al menos estructura), diseño segundo

**AP-02: WordPress sin Seguridad**
- Plugins sin actualizar, credenciales débiles, sin backups
- Resultado: pirateo, malware, pérdida de datos
- **Regla**: Updates automáticas, backups diarios, firewall (Wordfence)

**AP-03: Mobile Last**
- Diseñar para desktop, "adaptar" a mobile como afterthought
- Resultado: sitio se rompe en phone, 60% de usuarios ven basura
- **Regla**: Mobile-first SIEMPRE (80% de tráfico en LATAM es mobile)

**AP-04: SEO como Afterthought**
- Terminar desarrollo, luego "agregar SEO"
- Resultado: URLs sin palabras clave, títulos genéricos, estructura caótica
- **Regla**: SEO desde la arquitectura (URLs, headings, meta, sitemap)

**AP-05: Launch and Leave**
- Publicar y no monitorear
- Resultado: crash sin saber, errores no reportados, sitio lento después de 6 meses
- **Regla**: Monitoreo obligatorio: uptime + performance + analytics

**AP-06: Scope Creep Visual**
- "Solo un cambio más en el diseño" x 20 iteraciones
- Resultado: proyecto que debería 3 semanas → 12 semanas
- **Regla**: Congelar diseño en Sprint 1. Change requests formales después.

## 5 Decisiones de Diseño (Design Decisions)

**DD-01: Mobile-First SIEMPRE**
- >75% del tráfico en LATAM es mobile
- Wireframe: empezar en 320px, escalar a 1440px
- Testing: mobile primero (Safari iPhone), desktop segundo
- Resultado: sitio rápido, responsive natural, no "hack" de CSS

**DD-02: PageSpeed ≥80 es Requisito No Negociable**
- Impacta SEO (Google ranking) + conversión (cada 100ms = -1% conversión)
- Técnicas: lazy loading, compresión imágenes, caché, CDN
- Herramienta: Vercel, Netlify (auto-optimize) mejor que shared hosting

**DD-03: No-Code Primera Opción para Landing e Institucional**
- Razón: menor costo mantenimiento, cliente puede editar, no requiere dev
- Webflow > WordPress > Custom React (orden de preferencia)
- Escalar a código solo si requerimientos específicos (app web, integraciones complejas)

**DD-04: E-Commerce = Plataforma Especializada**
- NUNCA custom-build carrito + pagos
- Shopify, WooCommerce, TiendaNube tienen todo listo
- Custom solo si >1000 SKUs + lógica específica (B2B, marketplaces)

**DD-05: Copywriting = IA + Revisión Humana**
- IA genera estructura + copy inicial (ChatGPT, Claude, Jasper)
- Humano revisa tono, hace ajustes, agrega stories personales
- No 100% IA (suena robótico) ni 100% humano (costo x10)

**DD-06: Training Obligatorio**
- Nunca entregar sin enseñar cliente a actualizar
- 1 hora mínimo: admin panel, editables, analytics
- Video de 10min grabado para referencia futura

## Fallbacks Operativos

| Escenario Crítico | Fallback Técnico | SLA Respuesta | Propietario |
|-------------------|------------------|---------------|-------------|
| PageSpeed <60 post-launch | Image optimization + caché rules + CDN | <24h | Dev |
| Formulario no envía emails | Debug SMTP + configure alternative (Zapier) | <4h | Dev |
| Cliente no tiene contenido | Generate con IA + placeholder images + scheduled review | T+3 días | PM |
| DNS propagation delays | Temporary URL + migration documentation | 24-48h | Ops |
| Pasarela rechaza cliente | Ofrecer alternativa local o defer pagos | <48h | PM |
| Broken links descubiertos | Audit + fix all + retest | <24h | QA |
| SSL certificate issues | Renew / reinstall (Let's Encrypt auto-renewal) | <2h | Ops |
| Rediseño mid-project | Congelar + change request formal | En reunión | PM |
| Sitio lento después de 6 meses | Performance audit + caching optimization | <1 semana | Dev |
| Acesso admin credentials perdido | Password reset / panel recovery | <1h | Ops |
