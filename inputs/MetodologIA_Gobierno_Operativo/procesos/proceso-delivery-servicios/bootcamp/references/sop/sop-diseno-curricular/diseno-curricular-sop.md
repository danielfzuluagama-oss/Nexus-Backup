# SOP: Diseño Curricular de Bootcamp

**Versión:** 2.0 | **Vigencia:** 2026-01 | **Dueño:** Especialista Curriculum | **Última Actualización:** 2026-03-24

---

## Identificación

- **Código SOP**: SOP-DC-BC
- **Proceso Padre**: Entregar Bootcamp (Ver: entregar-bootcamp-proceso.md)
- **Fase**: Diseño Curricular (T-21 a T-7, 14 días)
- **Responsable Principal**: Especialista Curriculum (content + structure)
- **Responsable Secundario**: Facilitador Lead (pedagogy + facilitation playbook)
- **Stakeholders**: Tech Ops (platform), Account Manager (client alignment), Facilitador Team (training)
- **Gate**: Curriculum Readiness (T-7) - APROBADO o ESCALAR
- **Output hacia**: SOP-OC-BC (Onboarding Cohorte)

---

## Objetivo Binario

Producir curriculum completamente customizado (semana por semana, sesión por sesión) que:
- [ ] Convierte bootcamp type template en experiencia coherente para contexto específico cliente
- [ ] Incluye 15 lesson plans detalladas (3 semanas × 5 días × 1 sesión)
- [ ] Capstone rubric con 0-10 scale per 5 dimensions (concepto, ejecución, polish, impacto, presentation)
- [ ] Facilitador playbook 20-30 páginas (pedagogy, talking points, timing, handling edge cases)
- [ ] Participant materials (pre-work, handouts, templates, datasets)

---

## Supuestos & Límites

**Supuestos**:
1. Account Manager proporciona context memo T-21 (cohort profile, project brief, success criteria)
2. Bootcamp type template existe y es applicable (no crear curriculum from scratch)
3. Facilitador Lead tiene experiencia ≥1 bootcamp previo en modalidad
4. Tech infrastructure (Slack, Notion, Zoom) pre-approved T-21

**Límites (No cubierto)**:
- Desarrollo de nuevo bootcamp type (solo customización de tipos existentes BC-01 a BC-05)
- Traducción a idiomas otros que español
- Facilitator training intensiva (máximo: walkthrough + 1 practice session)
- Post-bootcamp curriculum evolution (feedback loop es separado)

---

## Trigger & Precondiciones

**Trigger**: Bootcamp confirmado + Cohort profile compartido + Project brief recibido

**Precondiciones**:
- Bootcamp type seleccionado (BC-01 a BC-05)
- Cohort size y composition conocida
- Project brief con contexto, constraints, success criteria
- Facilitator Lead asignado
- Tech infrastructure approved

## Proceso Paso-a-Paso (T-21 a T-7)

### T-21 a T-18: Context Analysis + Template Adaptation

**Responsable**: Especialista Curriculum (16 hours)

**Pasos**:

1. **Audit baseline curriculum** (2 hours):
   - Open template curriculum for bootcamp type
   - Review: learning objectives, week breakdown, session structure
   - Identify: customization points, flexibility areas

2. **Analyze cohort + context** (3 hours):
   - Cohort composition: roles, seniority, industries
   - Current skill level (baseline assessment)
   - Pain points + motivation (why are they here?)
   - Company tech stack, processes, constraints
   - Previous bootcamp experience (if any)
   - Learning modality preference (async vs. sync)

3. **Clarify project brief** (2 hours):
   - Problem statement: what are they solving?
   - Success criteria: how will we measure success?
   - Constraints: time, budget, technical, organizational
   - Scope: MVP scope vs. stretch goals
   - Stakeholders: who cares about results?

4. **Document context memo** (1 hour):
   - Create 1-page summary of findings
   - Share with Facilitador Lead for review
   - Flag any high-risk areas (scope too big, skills gap too large, etc.)

5. **Identify customization gaps** (2 hours):
   - Which content needs localization (examples, case studies)?
   - Which tech stack changes are needed?
   - Which sessions need depth increase/decrease?
   - Template modifications needed

**Output**: Context memo + customization checklist

---

### T-18 to T-14: Curriculum Mapping + Week Structure

**Responsable**: Especialista Curriculum + Facilitador Lead (12 hours)

**Pasos**:

1. **Design week-by-week flow** (3 hours):
   - **Week 1**: Foundations + first project iteration
     - Monday: Intro to bootcamp + context
     - Tue-Thu: 3 foundational concepts (3 days × 60 min = 180 min)
     - Friday: Group showcases
   - **Week 2**: Depth + team integration
     - Monday: Recap + connection to week 1
     - Tue-Thu: 3 advanced concepts + squad project work
     - Friday: Progress showcase
   - **Week 3**: Mastery + capstone prep
     - Monday: Synthesis + capstone briefing
     - Tue-Wed: Intensive project sprints (minimal teaching)
     - Thu: Rehearsal
     - Fri: Presentations

2. **Define learning objectives per week**:
   - Week 1: "By end of week, participants can [objective 1], [objective 2], [objective 3]"
   - Week 2: "By end of week, participants can [objective 4-6]"
   - Week 3: "By end of week, participants have shipped [artifact]"

3. **Outline session-by-session content** (4 hours):
   - For each session (15 total: 3 weeks × 5 days × 1 sync session/day):
     - Title + topic
     - Learning objective
     - Duration (60 min default)
     - Format (lecture, demo, hands-on, squad work)
     - Instructor + resources needed
     - Prerequisite knowledge
     - Async work assignment

4. **Create capstone rubric** (2 hours):
   - Define success criteria (5 dimensions: concept, execution, polish, impact, presentation)
   - Create 0-10 scale per dimension
   - Draft exemplar (what 8/10 looks like)
   - Test rubric with Facilitador (does it measure what matters?)

5. **Identify resource needs** (2 hours):
   - Tech tools: which platforms/APIs/licenses?
   - Content: readings, videos, templates, datasets
   - Guest speakers: domain experts, success stories
   - External support: freelancers, vendors

**Output**: Session-by-session curriculum outline + capstone rubric + resource list

---

### T-14 to T-10: Content Development + Lesson Planning

**Responsable**: Especialista Curriculum + Facilitador Lead (16 hours)

**Pasos**:

1. **Develop session content** (8 hours):
   - For high-customization sessions (5-7 sessions):
     - Create slides/deck
     - Write facilitator notes (talking points, timing, transitions)
     - Design any interactive elements (polls, breakouts, etc.)
     - Source/customize examples (use company context where relevant)
   - For low-customization sessions (8-10):
     - Adapt existing content (swap examples, update timings)
     - Customize case studies to industry

2. **Create lesson plan template** (1 hour):
   - Standard structure for all facilitators:
     - Objective (what will participants learn?)
     - Pre-work (what should they know?)
     - Opening (5 min): Hook + context
     - Teach (20 min): Concept + demo
     - Practice (20 min): Hands-on, guided
     - Apply (15 min): To their project context
     - Close (5 min): Summarize, preview next

3. **Develop facilitator playbook** (4 hours):
   - Comprehensive guide for facilitator (20-30 pages):
     - Overview of bootcamp philosophy + pedagogy
     - Week-by-week teaching notes
     - Session-by-session: objectives, timing, talking points
     - Common questions + answers
     - Differentiation strategies (if someone is lost)
     - Tech troubleshooting guide
     - Squad management tips
   - Include: discussion prompts, story ideas, energizers

4. **Create participant materials** (3 hours):
   - Pre-work assignments (Week 0): Baseline assessment + primer
   - Session handouts: 1-page takeaway per session
   - Template library: Reusable frameworks, docs, forms
   - Project checklist: Milestones + submission deadlines
   - Resource library: Readings, videos, tools, links

**Output**: Session content (slides/docs) + facilitator playbook + participant materials

---

### T-10 to T-7: Tech Setup + Facilitator Training

**Responsable**: Tech Ops + Facilitador Lead (12 hours)

**Pasos**:

1. **Configure learning platform** (4 hours by Tech Ops):
   - **Slack**: Channels (#general, #squad-[name], #office-hours, #help, #wins)
   - **Notion**: Database of lessons, resources, templates (searchable)
   - **Zoom**: Recurring links for sync sessions, recording setup
   - **LMS/Drive**: Host participant materials, assignments
   - **Project tracking**: Airtable/Linear for squad milestones
   - Test all integrations (Slack → Notion, Zoom recording → Drive)

2. **Train facilitator team** (6 hours):
   - **Session 1 (3 hours)**: Facilitador Lead + Asistente(s)
     - Walkthrough of playbook (page by page)
     - Pedagogy discussion (why we teach this way)
     - Tech platform tour (how to use each tool)
   - **Session 2 (3 hours)**: Run one session "live"
     - Asistente facilitates; Facilitador Lead watches
     - Feedback loop (what worked, what didn't)
     - Refinements to session plan
     - Build confidence

3. **Conduct tech dress rehearsal** (2 hours):
   - Full simulation of Week 1, Day 1:
     - Facilitador teaching from home (hybrid setup)
     - Asistente in home office
     - Tech ops watching (ensure recording, audio, video quality)
     - Simulate participant questions, technical issues
     - Iterate if needed

**Output**: Fully configured + tested platform, trained facilitator team, tech operational playbook

---

### T-7: Curriculum Readiness Gate

**Owner**: Especialista Curriculum (with Facilitador Lead approval)

**Checklist**:
- [ ] Curriculum customized + finalized
- [ ] Learning objectives clear + measurable
- [ ] Capstone project defined + rubric created
- [ ] All 15 sessions have lesson plans
- [ ] Facilitator playbook complete + trained team
- [ ] All materials ready (participant handouts, templates, datasets)
- [ ] Platform configured + tested
- [ ] Facilitator team confident + ready

**Gate Decision**:
- **APPROVED**: Proceed to Phase 2 (Onboarding)
- **NEEDS WORK**: Specify what's incomplete, reassign (max 2-day slip)

## Customization Guidelines by Bootcamp Type

### BC-01: Office Automation + AI
**Customization Points**:
- Company's current M365 setup (what's deployed, what's missing)
- Top 3-5 pain points (what gets automated first)
- Company-specific workflows (example: approval routing for POs)
- Security/governance requirements
- **Customize**: 60% of content (examples, workflows, governance)

### BC-02: Sales with AI
**Customization Points**:
- Sales process (how does this company sell?)
- ICP definition (ideal customer profile)
- Current CRM setup (Salesforce, HubSpot, other)
- Sales stack (tools in use)
- Go-to-market motion (inbound, outbound, hybrid)
- **Customize**: 70% of content (use real deal examples)

### BC-03: Ways of Working
**Customization Points**:
- Current operating model (waterfall? agile? chaos?)
- Org structure (distributed, co-located, hybrid)
- Company culture (autonomous, hierarchical, experimental)
- Tech stack (tools in use for planning, knowledge)
- Business model (SaaS, consulting, manufacturing, etc.)
- **Customize**: 50% of content (frameworks apply universally, implementation varies)

### BC-04: Custom Agents
**Customization Points**:
- Company's LLM preference (OpenAI, Anthropic, open-source)
- API integrations needed (Salesforce, HubSpot, custom systems)
- Data available for RAG (retrieval-augmented generation)
- Use cases (what problems will agents solve?)
- Security/compliance (data handling, output review)
- **Customize**: 80% of content (very context-specific)

### BC-05: No-code Apps
**Customization Points**:
- Platform choice (Bubble, FlutterFlow, Airtable, other)
- Problem to solve (is it well-defined or ideation-stage?)
- Target users (internal or external customers)
- Integration needs (if any)
- Success definition (viral adoption or internal tool)
- **Customize**: 40% of content (platforms are standardized, problems vary)

## Casos Borde (Curriculum Design)

**Caso 1: Cohort skills muy heterogéneo (algunos advanced, algunos beginner)**
Trigger: Curriculum builder notas que skill gap es >2 niveles
Decision: Diseñar curriculum para intermediate (middle ground) + crear supplementary office hours para stragglers
- Week 1 día 2: Beginner catch-up sessions (extra 1h office hours)
- Week 2: Intermediate advanced extensions (for strong participants)
Fallback: Si gap >3 niveles → sugiere cohort split (2 cohorts, diferentes pacing)

**Caso 2: Project scope cliente vs. Feasible en 3 semanas = mismatch (T-14)**
Trigger: Client pide MVP que requiere 8 semanas, pero bootcamp es 3 semanas
Decision: Early conversation with Account Manager + Client:
- Option A: Reduce scope a truly MVP (2-3 core features, rest roadmapped)
- Option B: Extend bootcamp to 4 semanas (cost change)
- Option C: Pivot to "proof of concept" (demo, not MVP)
Escalate if client insists on full scope.

**Caso 3: Facilitador Lead solicita currículum change T-10 (after draft complete)**
Trigger: "Encontré un gap, necesito reorganizar weeks"
Decision: If cambios <10% del contenido, approve. If >10%: evaluate impact.
- Create timeline (can we absorb sin delay?)
- Si sí: approve + adjust
- Si no: use como-está, document feedback para próximo cohort
Principle: Incremental improvement > perfect later

**Caso 4: Tech stack cliente diferente de template asumido**
Trigger: Template asume JavaScript, pero cliente usa Python. O asume Bubble, cliente usa Airtable.
Decision: Curriculum es framework-agnostic (ejemplos de concepts, no tech específico)
- Swap examples/exercises al lenguaje cliente
- Facilitador adapta live demo
- Mismo curriculum, diferente syntax
If tech change es radical (e.g., no-code → code): evaluate 1:1 con Facilitador Lead + VP Contenido

**Caso 5: Rubric criteria no align con client success definition**
Trigger: Client dice "lo importante es que sea rápido", pero rubric emphasizes polish
Decision: Revise rubric con client input:
- Get client's 5 success criteria
- Map a dimensiones del rubric
- Reweight if needed (e.g., "speed" sube de 20% a 40%)
Principle: Rubric must measure what client cares about

---

## Anti-Patterns (QUÉ NO HACER)

- NO usar curriculum template sin customización (every context is different)
- NO crear rubric sin client input (risk: measuring wrong things)
- NO comprometer lesson plan development (vago = vague facilitation)
- NO asignar facilitator team training a asistente (lead debe entrenar)
- NO pasar curriculum gate si lesson plans <90% complete

---

## Fallbacks Operativos

| Falla | Fallback |
|-------|----------|
| Context memo incomplete T-21 | Kick-off call express (2h) con Account Manager + Client → document findings |
| Facilitador Lead unavailable T-18 | Especialista Curriculum procede con asistencia de senior facilitator (no ideal, pero viable) |
| Capstone rubric contested | Revisión joint con cliente T-14 (antes de finalizarlo) |
| Tech platform not ready T-10 | Continue curriculum design, defer platform config to T-5 (critical path: education, not tech) |
| Especialista Curriculum overload | Escalate to VP Contenido (puede traer segundo especialista) |

## Templates Included

### Template 1: Session Lesson Plan

```
SESSION: [Title]
Week: [1-3] | Day: [Mon-Fri] | Duration: [60 min]
Facilitator: [Name] | Asistente: [Name]

LEARNING OBJECTIVE
By the end of this session, participants will be able to:
- [Objective 1]
- [Objective 2]

PRE-WORK
- [Reading, video, or prep work]
- [Estimated time: X min]

OPENING (5 min)
- Hook: [Story, question, or scenario]
- Context: [Why does this matter?]
- Agenda: "Here's what we'll do today"

TEACH (20 min)
- Concept: [Name of concept]
- Why it matters: [2-3 sentences]
- Show example: [Walkthrough of concept in action]
- Talking points: [Key ideas to emphasize]
- Common questions: "Won't this...?" → [Answer]

PRACTICE (20 min)
- Activity: [Hands-on task]
- Instructions: [Step-by-step]
- Facilitator role: [Circulate, ask probing questions]
- Success signal: [What does good look like?]

APPLY (15 min)
- Context: [Translate to participant's project]
- Prompt: [How would you use this for your problem?]
- Squad discussion: [15 min of squad-level problem-solving]

CLOSE (5 min)
- Recap: [One-sentence summary]
- Preview: [What's next session?]
- Homework: [If applicable, async work for tonight]

RESOURCES
- [Slides/deck]
- [Template/tool]
- [Reading/reference]
- [Recording link (post)]
```

### Template 2: Capstone Rubric

```
CAPSTONE PROJECT RUBRIC (0-10 scale)

Dimension 1: CONCEPT CLARITY (Does the solution match the problem?)
- 8-10: Crystal clear problem statement, solution is well-aligned, no ambiguity
- 6-7: Clear problem, solution mostly aligned, minor unclear areas
- 4-5: Problem somewhat clear, solution loosely aligned
- 0-3: Problem or solution unclear or misaligned

Dimension 2: EXECUTION QUALITY (Is the solution built well?)
- 8-10: All features working, polished, no crashes, performant
- 6-7: Features working, minor bugs, acceptable performance
- 4-5: Core features working, some bugs, slow in places
- 0-3: Features partially working, multiple bugs, slow

Dimension 3: POLISH (Does it feel like a real product?)
- 8-10: Design thoughtful, flows intuitively, user documentation
- 6-7: Decent design, mostly intuitive, some documentation
- 4-5: Basic design, some friction, minimal documentation
- 0-3: Rough design, confusing, no documentation

Dimension 4: IMPACT (Will users actually use this?)
- 8-10: User testing ≥5 people, ≥80% positive feedback, real use case
- 6-7: User testing 3-4 people, ≥70% positive, relevant use case
- 4-5: User testing 1-2 people, mixed feedback, somewhat relevant
- 0-3: No user testing or feedback strongly negative

Dimension 5: PRESENTATION (Can they articulate the vision?)
- 8-10: Clear narrative, passionate delivery, compelling visuals
- 6-7: Clear story, good delivery, decent visuals
- 4-5: Somewhat clear, adequate delivery, basic visuals
- 0-3: Unclear or weak delivery

TOTAL SCORE: __/50 (or convert to 0-10)
```

## Quality Assurance

**Pre-bootcamp curriculum review** (by Facilitador Lead):
1. [ ] Objectives are measurable + achievable in 3 weeks
2. [ ] Content scaffolds well (foundations → advanced → synthesis)
3. [ ] Project is realistically scoped (can be completed in 3 weeks)
4. [ ] Materials are error-free + professionally formatted
5. [ ] Facilitator feels confident teaching this
